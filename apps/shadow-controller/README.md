# Shadow Controller Desktop

The Tauri + React desktop application is the configuration and monitoring surface for the persistent Shadow Coordinator. On Windows, it starts the Coordinator as a separate headless process, registers it for user-login autostart in release builds, and can request a controlled stop. A single-instance file lock protects the process; closing the GUI does not stop it.

Google sign-in runs in the system browser through a temporary loopback callback; Firebase identity is checked before the refresh credential is stored in the operating system credential store. The frontend receives account identity and pairing status through Tauri commands, never the Firebase ID token. The WebView uses a restrictive Content Security Policy for local assets, IPC and the app's font sources. A stable server ID is also stored in the credential store. The Overview can register this server once to a signed-in account in Firestore and remove that pairing with confirmation; account documents can only be created once, and Firestore rules deny cross-account access and all unlisted data. The Security screen lists authorized clients and can revoke them with confirmation. Client enrollment and interactive sign-in/pairing have not yet been verified on Windows. Branch CI uploads a debug Windows executable for seven days so the interactive flow can be checked without installing Rust locally; the debug build does not enable release autostart. The sidebar reports the background process state and can start or stop the Coordinator. The Jobs screen is connected to the local SQLite store through Tauri commands: it can list queued jobs, inspect redacted event history, add a clearly marked local queue entry, and cancel it. Queue entries are persisted on this device and do not dispatch work or invoke models. The Coordinator contains a CI-compiled WSS relay supervisor that reads Firebase credentials from the OS credential store, reconnects with backoff and supports remote queue submission, status, list and cancellation. Set the user environment variable `SHADOW_RELAY_URL` to the relay HTTPS base URL; without it, the Coordinator stays local. The relay has not been deployed, so end-to-end connection, authentication and pairing are unverified. Queue entries still do not run production workers, and manual retry and asset tools are not implemented server-side. Other operating systems remain unverified.

Google sign-in opens the Firebase-hosted HTTPS authentication portal at `https://shadow-controller-20261103.firebaseapp.com`, matching the Firebase Auth helper domain configured in the portal. After Google authentication, select **Return to Shadow Controller**; the browser may ask permission to connect to the local desktop app. The desktop accepts the callback only from the hosted portal, validates the Firebase identity and session, and stores its refresh credential in the operating system credential store. If sign-in remains pending, use **Cancel sign-in** in the desktop app and retry. The portal is a separate React/Vite app in `auth-portal`. Build and deploy it from the repository root with `npm ci --prefix apps/shadow-controller/auth-portal`, `npm run build --prefix apps/shadow-controller/auth-portal`, then `firebase deploy --only hosting --project shadow-controller-20261103`.

## Development

```powershell
npm install
npm run dev
```

Building or running the native Tauri application requires the platform prerequisites, including Rust. GitHub Actions will provide the release builds so end users do not need the Rust toolchain.
