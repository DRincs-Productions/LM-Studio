# Shadow Controller Desktop

The Tauri + React desktop application is the configuration and monitoring surface for the persistent Shadow Coordinator. On Windows, it starts the Coordinator as a separate headless process, registers it for user-login autostart in release builds, and can request a controlled stop. A single-instance file lock protects the process; closing the GUI does not stop it.

Google sign-in runs in the system browser through a temporary loopback callback; Firebase identity is checked before the refresh credential is stored in the operating system credential store. The frontend receives account identity and pairing status through Tauri commands, never the Firebase ID token. The WebView uses a restrictive Content Security Policy for local assets, IPC and the app's font sources. A stable server ID is also stored in the credential store. The Overview can register this server once to a signed-in account in Firestore and remove that pairing with confirmation; account documents can only be created once, and Firestore rules deny cross-account access and all unlisted data. The Security screen lists authorized clients and can revoke them with confirmation. Client enrollment and interactive sign-in/pairing have not yet been verified on Windows. Branch CI uploads a debug Windows executable for seven days so the interactive flow can be checked without installing Rust locally; the debug build does not enable release autostart. The sidebar reports the background process state and can start or stop the Coordinator. The Jobs screen is connected to the local SQLite store through Tauri commands: it can list queued jobs, inspect redacted event history, add a clearly marked local placeholder and cancel jobs. Authenticated `codex.execute` and `narrative.generate` requests are claimed FIFO by the single-active-job Coordinator. Generic tasks run through server-side Codex. Narration runs the local Writer, up to five Gemini CLI review calls, then a read-only Codex final check, saves stage evidence, unloads the Writer and publishes a hash-verified Markdown result to the configured OneDrive rclone remote. Writer/reviewer processes have bounded execution and output capture; cancellation and an unreconciled child-process marker pause queue dispatch for manual verification. Set `SHADOW_RELAY_URL` and configure the LM Studio API, Gemini CLI, Codex CLI and the `imagecloud:` rclone remote for narration. The Cloudflare bootstrap endpoint is reachable but remains in `setup`; its deployed version has no Durable Object binding and is not the relay implementation in this repository. Repository relay tests cover closed-state handling, Firebase identity and pairing checks, device proof, and offline-server rejection; live authentication and end-to-end job/file transfer remain unverified. Coordinator source now implements explicitly requested retries for failed jobs and metadata for verified narrative files; the Rust build still needs CI verification. Other operating systems remain unverified.

Google sign-in opens the Firebase-hosted HTTPS authentication portal at `https://shadow-controller-20261103.firebaseapp.com`, matching the Firebase Auth helper domain configured in the portal. After Google authentication, select **Return to Shadow Controller**; the browser may ask permission to connect to the local desktop app. The desktop accepts the callback only from the hosted portal, validates the Firebase identity and session, and stores its refresh credential in the operating system credential store. If sign-in remains pending, use **Cancel sign-in** in the desktop app and retry. The portal is a separate React/Vite app in `auth-portal`. Build and deploy it from the repository root with `npm ci --prefix apps/shadow-controller/auth-portal`, `npm run build --prefix apps/shadow-controller/auth-portal`, then `firebase deploy --only hosting --project shadow-controller-20261103`.

Narration requests use the `narrative.generate` v1 queue. The Coordinator runs the built-in Hemmingway Writer in LM Studio, deterministic checks and up to five Writer revisions, then makes one final edit with `venice/venice-uncensored-1-2` through OpenCode. The editor has access to the approved narrative skills and no other tools. If Venice fails, the server preserves the latest usable draft and reports the reviewer outcome in the manifest. It unloads the Writer, publishes the selected English Markdown scene to `imagecloud:NarrationWorker/final/<jobId>/scene.md`, and verifies the remote SHA-256 before returning the reference. The client downloads and verifies the file with `get_narration_result`. The server user's authenticated OpenCode Venice account and rclone configuration must be available to the Coordinator.

An experimental local Qwen path can be selected with `SHADOW_NARRATION_REVIEW_BACKEND=qwen`; it uses `qwen2.5-14b-instruct-abliterated-v2` by default and unloads the Writer before loading Qwen. The default mode is `direct-edit`; `SHADOW_NARRATION_REVIEW_MODE=feedback-loop` enables up to five Qwen review/Writer-revision cycles followed by a Qwen final edit. The Qwen option is not the production default: a 6 November 2026 normal-scene test found an unsupported PASS on an explicit event-order defect, and direct-edit runs returned the Writer draft unchanged. Keep Gemini → Writer revisions → Codex as the default pending a successful quality evaluation. The comparison report is `production-tests/shadow-narration/20261106_qwen-reviewer-mode-comparison/report.md`.

## Development

```powershell
npm install
npm run dev
```

Building or running the native Tauri application requires the platform prerequisites, including Rust. GitHub Actions will provide the release builds so end users do not need the Rust toolchain. The server release workflow runs `node --check coordinator/src/narration.mjs` before packaging to catch syntax errors in the bundled narration worker and its prompts.

Before loading the Writer, the Coordinator checks `GET /v1/models`. If a local HTTP endpoint is unavailable, it starts LM Studio with `lms server start` on the configured port, binds it to loopback, and waits for the models endpoint to respond. The default endpoint is `http://127.0.0.1:1234`. Remote endpoints must already be reachable. The API stays running for later jobs.
